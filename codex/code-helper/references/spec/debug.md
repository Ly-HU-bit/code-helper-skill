#描述
这是一份关于如何debug的要求：


#要求
用户input中提供了相关报错信息的，优先处理
出错部分尽可能保留用户原函数及其风格，不要直接删除出错部分，如果不符合优化、style要求，可以后续将其注释掉并重新编写
在output中的说明部分，应该详细指出错误根源，提供1次出错的运行实例，并指出实际修改措施，为用户此后coding提供总结性建议
Quick/Standard 报告说明文件名、行号、根因和修复即可，完整代码对照以
`changes.patch` 为准。Deep 报告可额外展示必要的局部 diff。

#执行检查清单
进行debug时，逐项检查以下内容：

##错误定位
- [ ] 阅读了所有报错信息（编译错误、运行时异常、测试失败输出）
- [ ] 定位到了错误的精确位置（文件名+行号）
- [ ] 区分了语法错误、逻辑错误、运行时错误

##错误分析
- [ ] 能用一句话描述错误根因
- [ ] 能提供一个具体的输入导致错误输出的运行实例
- [ ] 检查了是否同一错误在多处出现

##修复原则
- [ ] 出错的原始代码未被删除（注释掉保留，在注释中说明原因）
- [ ] 修复不引入新的bug
- [ ] 修复不改变程序的主框架/架构
- [ ] 修复后通过了所有现有测试

##常见错误类型速查
- [ ] 空指针/None引用：对可能为null的对象调用方法前未检查
- [ ] 边界错误：循环条件off-by-one（< vs <=）
- [ ] 逻辑反转：条件判断取反（!flag 写成了 flag）
- [ ] 变量覆盖：局部变量名与成员变量同名导致shadowing
- [ ] 拼接错误：字符串拼接遗漏空格/分隔符
- [ ] 类型转换：整数除法导致精度丢失（int/int = int）

##文档要求
- [ ] doc中说明了错误的根本原因（非表面现象）
- [ ] 报告提供了精确文件与行号，changes.patch 包含完整代码对照
- [ ] doc中提供了1个触发错误的运行实例
- [ ] doc中说明了实际修改措施
- [ ] doc中给出了预防性总结建议
